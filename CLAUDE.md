# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `pnpm install` — install dependencies.
- `pnpm dev` — start Next.js dev server.
- `pnpm build` — build production app.
- `pnpm start` — start built app.
- `pnpm lint` — run ESLint.
- `pnpm typecheck` — run TypeScript with `tsc --noEmit`.
- `pnpm format` — run Prettier over `**/*.{ts,tsx}`.
- `pnpm db:generate` — generate Drizzle migrations from schema changes.
- `pnpm db:migrate` — apply Drizzle migrations.
- `pnpm db:push` — push schema changes directly.
- `pnpm db:studio` — open Drizzle Studio.
- `pnpm auth:generate` — regenerate Better Auth Drizzle schema into `drizzle/schemas/auth-schema.ts` from `lib/auth/auth.ts`.

No test runner or `test` script is configured in `package.json`; there is no single-test command yet.

## Architecture

This is a Next.js 16 App Router asset-management app using React 19, TypeScript strict mode, Tailwind CSS v4, shadcn-style UI primitives, Better Auth, and Drizzle ORM with PostgreSQL.

Route groups split auth and dashboard UI:

- `app/(auth)/...` contains login, forgot/reset password, and change-password flows. Forms call colocated server actions.
- `app/(dashboard)/...` contains protected dashboard modules for setup, network, and asset workflows. Most feature folders follow `page.tsx` list views, `new/page.tsx`, `[id]/edit/page.tsx`, `_components/*Form.tsx`, `column.tsx`, and `action.ts` server actions.
- `app/api/auth/[...all]/route.ts` exposes Better Auth handlers.
- `app/(dashboard)/layout.tsx` requires a user, loads role-filtered sidebar data, and wraps content in sidebar layout.

Data access is server-first:

- `data/*.ts` files are `server-only` query modules. They usually call `requireUser()` and `requirePermission()` before Drizzle queries, then return view-ready data.
- `data/require-user.ts` wraps Better Auth session lookup and redirects unauthenticated users to `/login`.
- `data/sidebar.ts` builds the sidebar from active role/menu/module mappings for the current user.
- `lib/helper.ts` centralizes pagination params/meta/response helpers used by list pages and `components/ui/data-table.tsx`.

Auth and authorization:

- `lib/auth/auth.ts` configures Better Auth with Drizzle adapter, username and phone-number plugins, Next cookies, and WhatsApp OTP sending through `lib/fonnte.ts`.
- On username sign-in, `lib/auth/auth.ts` stores current permission names on the new session and deletes other sessions for that user.
- `lib/auth/permission-query.ts` computes permission names from active user roles.
- `lib/auth/permission.ts` exposes `requirePermission()` for pages/loaders and `authorizeAction()` for server actions.
- Client auth helpers live in `lib/auth/auth-client.ts`.

Database layer:

- `drizzle/db.ts` creates a PostgreSQL pool using `env.DATABASE_URL` and sets timezone to `Asia/Jakarta`.
- `drizzle/schema.ts` re-exports split schema files from `drizzle/schemas/*`.
- `drizzle/schemas/auth-schema.ts` is generated by Better Auth but also participates in app relations; inspect generated changes before accepting them.
- `drizzle/migrations/` stores generated SQL migrations.
- `drizzle.config.ts` reads `DATABASE_URL` through `lib/env.ts` and points schema to `drizzle/schema.ts`.

Validation and forms:

- Form schemas live in `lib/formSchemas/*` using Zod.
- Client forms use React Hook Form with `zodResolver`, call server actions, show Sonner toasts, and navigate after success.
- Server actions validate with the same Zod schemas, set audit fields such as `createdBy` / `updatedBy`, and call `revalidatePath()` for affected list routes.

UI conventions:

- Shared primitives live in `components/ui/*`; app-level shared components live in `components/*`.
- Data tables use TanStack Table via `components/ui/data-table.tsx`, with pagination reflected in `page` and `size` URL search params.
- Import aliases use `@/*` from `tsconfig.json`; shadcn aliases are configured in `components.json`.

Environment:

`lib/env.ts` validates required server environment variables: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `MEKARI_API_BASE_URL`, `MEKARI_API_CLIENT_ID`, `MEKARI_API_CLIENT_SECRET`, and `FONNTE_TOKEN`.
